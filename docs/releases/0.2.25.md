# Rooms 0.2.25: direct samples with Cloudflare coordination

FL Studio **24.2.2.4597, 25.2.5.5319 and 26.1.7.5654** keep sharing supported notes and
controls in any host order. This build includes all 34 fixes from 0.2.24 and adds WebRTC sample
downloads. Exact FL fingerprints remain required; support for every FL patch is not claimed.

When you add a referenced sample, the receiver can download its bytes directly from another
participant. Cloudflare still authenticates the room, orders edits and manages locks. Note
CRDTs keep merging recorded/shared note changes. R2 stores the initial backup and supplies
downloads when a direct connection is unavailable.

## Changes explained

1. **Direct sample downloads.** Connected participants exchange file bytes over an encrypted
   WebRTC data channel instead of making an R2 read for every recipient.
2. **Automatic R2 fallback.** No connection, a missing source, an interrupted transfer or an
   occupied direct slot uses the existing R2 route without asking you to choose a transport.
3. **Native verification.** The receiver checks both length and SHA-256 before using a direct
   sample. Wrong content falls back; it cannot silently become the shared sample.
4. **Correct retry progress.** Bytes from a failed direct attempt are removed from progress
   before the R2 attempt starts, so a retry cannot count the same file twice.
5. **R2 pauses stay scoped to R2.** An available direct file can download during an R2 retry
   pause. The R2 cutoff still protects actual R2 requests.
6. **Per-session file credentials.** Cloudflare issues each connected native participant its
   own private file capability. The separate file connection cannot impersonate another room.
7. **No duplicate people.** A file companion does not occupy another participant slot or
   acquire musical edit locks.
8. **Room-scoped signaling.** The Worker forwards bounded offers, answers and ICE candidates.
   A file socket cannot submit musical edits or route signals to another room.
9. **Revocation on departure.** Leaving FL's room closes that participant's file companion.
   Replacing a companion revokes the previous one; closing only a companion keeps the room.
10. **Private local broker.** The app binds to loopback, requires a random per-launch token,
    rejects browser-origin requests and reads only explicitly registered source files.
11. **Isolated WebRTC worker.** A hidden sandboxed renderer owns the network channels, with
    no Node.js, filesystem, camera or microphone access.
12. **Bounded transfer work.** Two incoming and two outgoing slots per launch, 32 KiB chunks,
    queue limits and acknowledgments bound work rather than loading whole files.
13. **Correct concurrent admission.** Outgoing slots are reserved before filesystem awaits;
    simultaneous requests cannot slip past the limit. Launch limits are checked after awaits too.
14. **Changed-source handling.** Serving checks source size and modification time before/after
    reading. Removed or changed sources decline direct serving.
15. **Streaming cleanup.** Drain/close listeners are removed together, so long transfers do
    not accumulate listeners. Failed opens/stat calls release slots and handles.
16. **Session cancellation.** Reconnecting clears old registrations, readiness and pending
    downloads. Obsolete reads check their generation before sending the next chunk.
17. **Background service lifetime.** Closing the controls hides them while a launched FL
    remains alive. Reopening shows them; the hidden app exits after its last FL ends.
18. **Worker recovery and shutdown.** A crashed transport renderer can restart after signaling
    reconnects. Shutdown settles replies, removes IPC handlers and destroys the worker.
19. **Legacy fallback.** Older apps/relays continue through R2. Failure to prepare the optional
    direct service does not prevent a normal native launch. File signaling follows the same
    configured relay as room setup, including contributor builds against another server.
20. **Diagnostics and packaging.** Direct events record byte counts without source paths or
    capabilities. The portable app includes the worker, preload and WebSocket runtime.
21. **Reproducible testing.** CI runs actual Electron WebRTC transfers through a local Cloudflare
    emulator alongside native, relay and desktop suites.

## Verification and limits

Passed: 193 desktop tests, 32 native harness executables, 127 room/UI and 68 Files/UI checks,
76 local Cloudflare tests, original relay tests, native transfer/file-sync loopbacks and real
Electron folder/window/sidebar/recovery/package/portable checks.

Actual Electron channels transferred a 2,097,171-byte sample three times directly, including
two simultaneous downloads, through both emulator and deployed Cloudflare signaling. Each run
made exactly one R2 read for its deliberately forced fallback. These were two isolated launch
sessions on one computer, not two physical FL computers or a remote NAT test. There was no fresh
physical MIDI, arbitrary VST/FL patch or long internet soak test. The earlier FL24 recovery-save
stall remains an unresolved observation.

The signaling update is deployed to this fork's existing relay. No TURN subscription was added.
Initial R2 uploads/storage and platform/application budgets remain. Full projects and large
edit payloads keep their existing paths. Both sides need 0.2.25 for direct downloads.
